# 康联云：产品设计与项目亮点说明

## 1. 产品定位

“康联云”不是普通药店进销存，也不是只提醒吃药的单机工具。它解决的是长期慢病家庭中跨角色、跨地点的药事协同：安心用药成员提出需求，家庭管理员远程审批和购药，双方持续追踪资金、物流、收货核验、库存和费用凭证。

两个角色名称：

- 家庭协同端：原“子女端/管理员端”，负责配置、代购、审批、异常处置和审计。
- 安心用药端：避免使用让用户不舒服的“老人端”，负责查看用药、提交需求、确认信息和核验收货。

## 2. 本轮为什么这样改

原界面把 13 个功能全部平铺为一级菜单，顶部又重复四个快捷入口，虽然功能存在，但用户无法形成清晰的任务心智。本轮按照“总览—药事协同—购药履约—运营洞察—系统治理”重组信息架构。

设计依据来自公开的企业后台设计规范：

- [Ant Design 导航研究](https://ant.design/docs/spec/research-navigation/)建议功能超过六项时使用侧边导航，并根据任务或主题分组；搜索、通知、帮助和账号等工具型能力放在顶部。
- [Ant Design 工作台研究](https://ant.design/docs/spec/research-workbench/)强调工作台应按角色呈现核心数据、待办、关注事项和快捷操作，而不是简单堆放统计卡片。
- [Ant Design 列表页研究](https://ant.design/docs/spec/research-list/)强调列表要支持筛选、分析和逐层查看详情。
- [Ant Design 数据展示规范](https://ant.design/docs/spec/data-display/)强调按重要度、频率和关联性组织信息，并通过渐进披露避免一次展示全部字段。

因此药品列表保留高频判断字段，点击药名或国药准字号后，再从右侧打开完整“药品业务画像”。

## 3. 当前能力地图

### 药事协同

- 药品主数据：批准文号、品牌、规格、包装、厂家、参考价、图片、启停状态。
- 药品业务画像：关联方案数、在用方案数、低库存风险、购药次数、购药盒数、累计支出、相关成员、最近购药轨迹。
- 用药方案：服药频次、时段、每次用量、单盒可用天数、版本历史。
- 申请审批：药品不足、丢失、损坏、新处方、出行备药等原因。
- 申请二次确认：提交前确认药品明细和估算金额，提交后进入不可随意修改的审批流程。
- 风险中心：库存不足、3 天内高风险、30 天内临期、处置建议与业务跳转。

### 购药履约

- 购药记录：日期、时间、数量、价格、平台、线上/线下、有效期和收货状态。
- 家庭代购订单：实际价格、下单截图、快递公司、运单号和物流轨迹。
- 收货核验：安心用药成员拍照，并逐项核对数量、国药准字号和包装完整性。
- 异常闭环：数量或批准文号不符时不入库存，通知家庭管理员处理后重新开启核验。
- 资金台账：转账、购药扣款、余额调整、正负余额和资金凭证。
- 费用凭证档案：按购药记录查看凭证完整性、平台、金额、成员和业务状态。

### 运营洞察

- 年、月、周、日购药金额和次数。
- 平台、线上/线下、购药时段分析。
- 累计金额、订单次数、线上金额、线下金额和次均费用。
- 数据质量评分：药品档案完整性、成员绑定、停用档案等治理任务。
- 站内消息和可配置邮件通知。

### 安全与治理

- JWT 身份认证和角色权限控制。
- 人机验证、连续输错五次锁定、锁定剩余时间、管理员解锁和重置密码。
- BCrypt 密码存储；账号和密码不会作为系统默认提示展示。
- 关键操作审计日志。
- Excel 数据导出。
- 手机端自适应布局。

## 4. 企业演示数据

`sql/demo/20260808_seed_enterprise_demo.sql` 会生成：

- 20 条虚构药品主数据；
- 20 条关联用药方案；
- 20 条库存数据，其中包含低库存和临期场景；
- 1000 条跨三年的购药记录，覆盖京东健康、阿里健康、美团买药、叮当快药、医院药房、社区药店等平台和线上/线下渠道；
- 120 条已读/未读消息。

脚本不含真实手机号、邮箱和密码。它自动寻找数据库内现有的一个启用家庭管理员与一个启用安心用药成员。脚本通过版本表保证同一版本只导入一次，并在异常时回滚。

注意：所有带“示例”的药品、厂家、价格和凭证都属于演示数据，不能作为真实用药或购买依据。

## 5. 可以写进简历的项目亮点

可根据真实面试场景选用以下描述，不建议原封不动全部堆入简历：

1. 设计并实现面向长期慢病家庭的双角色药事协同平台，覆盖“需求申请—家属审批—远程代购—物流跟踪—收货逐项核验—库存入账—费用存证”的业务闭环。
2. 针对药品错发、少发风险，设计数量、国药准字号、包装完整性和现场照片的逐项核验机制；异常订单禁止入库并触发家属通知和重新核验流程。
3. 建立购药资金台账与多维费用分析模型，支持年/月/周/日、平台、渠道和时段维度统计，为家庭对账与低保材料整理提供可追溯数据。
4. 实现药品主数据业务画像，通过聚合查询在单一详情抽屉中展示关联方案、库存风险、累计购药支出、相关成员和最近购药轨迹。
5. 完成登录安全加固，包括 BCrypt、JWT、人机验证、失败锁定、倒计时提示、管理员解锁/重置和操作审计。
6. 将平铺式后台重构为按业务域组织的可折叠工作台，增加全局命令搜索、响应式移动端和按任务渐进披露的信息设计。
7. 构建 1180 条幂等企业演示数据集，覆盖跨三年多平台场景，用于统计、风险、凭证和性能演示；同版本重复执行自动跳过，异常自动回滚。

## 6. 后续高价值迭代顺序

1. 域名和 HTTPS：先解决密码在 HTTP 网络中可被窃听的问题。
2. 真实邮件服务：配置 SMTP/App Password，增加发送队列、重试和失败告警。
3. 物流开放平台：接入合法物流查询 API，替代手工维护物流节点。
4. OCR 与票据识别：从订单截图或小票提取平台、金额、时间和药品明细，人工确认后入库。
5. 药监数据校验：通过合规数据源验证批准文号、生产企业和药品状态。
6. 自动化测试：补充 Testcontainers 数据库集成测试和核心业务端到端测试。
7. 可观测性：增加请求追踪、业务指标、慢查询和异常告警。
