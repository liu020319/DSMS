# 家庭远程代购药流程说明

## 完整业务流程

1. 安心用药端选择申请原因和多种药品，系统按药品参考价计算预计金额并显示当前购药余额。
2. 进入二次确认页，核对药名、规格、盒数和预计金额；最终提交后不提供修改入口。
3. 系统立即生成家庭守护端站内消息。启用邮件后，同时向绑定家属的邮箱发送提醒。
4. 家庭守护端核对申请，填写实际单价、有效期、购买平台、下单时间，上传订单截图并登记物流公司和单号。
5. 系统按实际金额生成购药记录，并在资金台账中自动写入一笔负数扣款。余额允许为负数。
6. 家庭守护端可以持续补录物流轨迹，安心用药端查看订单、截图、物流单号和时间线。
7. 收到药品后必须上传药品合照，并逐项填写实收盒数、包装上的国药准字号和包装是否完好。
8. 全部一致时药品才计入库存；任一项不一致会进入收货异常、通知家庭守护端，处理补发或换货后再重新核验。
9. 统计中心按年、月、周、日、平台、线上/线下和下单时段展示购药次数与费用，Excel 同时导出明细和多张汇总表。

## 登录安全

- 登录前必须完成一次点击式安全验证；验证令牌两分钟有效且只能使用一次。
- 密码连续输错 5 次后锁定账号 15 分钟，登录页显示剩余倒计时。
- 家庭管理员可以单独解除锁定；重置密码时也会自动解除锁定。
- 点击式验证用于阻挡最基础的自动请求。正式公网环境如需要更强机器人识别，可再接入 Cloudflare Turnstile 等托管验证码。

## 数据库升级

服务器数据库按下面顺序执行：

```bash
read -s -p "请输入MySQL root密码: " MYSQL_ROOT_PASSWORD && echo
docker exec -i mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" medicine_system < sql/migrations/20260807_family_purchase_workflow.sql
docker exec -i mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" medicine_system < sql/migrations/20260807_security_and_receipt_verification.sql
unset MYSQL_ROOT_PASSWORD
```

执行前请先备份数据库。两个公开脚本必须按顺序执行，最后一个脚本增加账号锁定字段、收货状态和收货核验历史表。

生产账号、手机号和通知邮箱属于私有部署数据，不写入公开仓库。数据库结构升级完成后，应通过管理员页面创建账号并绑定家庭关系，或在服务器上单独执行不受 Git 管理的私有初始化脚本。

## Gmail 邮件提醒

代码不会保存 Gmail 登录密码。服务器启动前配置：

```bash
export MAIL_ENABLED=true
export MAIL_USERNAME='your-gmail@example.com'
export MAIL_APP_PASSWORD='Google生成的16位应用专用密码'
export MAIL_RECIPIENT='recipient@example.com'
```

Gmail 账号需要先开启两步验证并生成应用专用密码。不要使用 Gmail 日常登录密码，也不要把应用专用密码提交到 Git。

## 物流说明

当前版本支持京东物流、中通、申通、圆通、极兔等承运商的公司、单号、状态和轨迹时间线；家庭守护端可以补录轨迹，安心用药端可以打开统一查询链接核对。

真正自动同步承运商轨迹需要申请物流聚合平台的企业/个人 API 密钥。后续取得密钥后，可通过 `LOGISTICS_PROVIDER` 和查询服务接入，不需要重做订单数据结构。

## 重要边界

- 参考价格仅用于申请预算，最终费用以家庭守护端录入的实际订单价格和截图为准。
- 本系统记录家庭购药凭证，不提供诊断、剂量建议或药物相互作用判断。
- Excel 可作为整理后的家庭购药佐证，但是否被低保或民政部门采信，以当地实际材料要求为准。
