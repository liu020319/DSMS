# DSMS R3 全量测试报告

## 1. 结论

本次 R3 代码已通过 Java 编译、后端自动化测试、Spring Boot 可执行 JAR 打包和 Vue 生产构建。自动化测试共 10 项，结果为 10 通过、0 失败、0 异常、0 跳过。

本报告严格区分“已经由本机自动化验证”和“需要部署到阿里云后人工验收”的内容。由于当前桌面会话没有可调用的浏览器控制能力，也没有连接生产 MySQL，本报告不把手机真机视觉效果、生产数据库迁移和邮件到达情况写成已通过。

## 2. 本次覆盖的功能

1. 手机端弹窗固定在可视区域内，标题与关闭按钮保持可见，弹窗内容内部滚动。
2. 手机输入控件使用 16px 字号并限制双击缩放，降低聚焦后页面突然放大的概率。
3. 用药方案、购药记录、账号管理和药品档案的手机操作列改为窄列加下拉菜单，不再长期固定占据大半屏幕。
4. 左侧展开子菜单使用深色半透明背景，不再出现纯白色子菜单块。
5. 未读状态与业务状态分离：未读、已读待处理、已购买、配送中、待收货核验、已完成、收货异常。
   顶部铃铛每 30 秒轻量刷新一次未读数，当前页面读消息后会立即同步红点，不需要引入 MQ。
6. 家属登记订单时上传下单截图并填写预计到货时间；不依赖外部物流 API。
7. 安心用药端收货时上传照片，并核对实收盒数、国药准字号、包装、规格和剂量。
8. 安心用药端可以访问今日用药库存接口，晨间、午间、晚间演示方案均有数据。
9. 权限分为 ADMIN 平台管理员、GUARDIAN 家庭守护人、ELDER 安心用药成员；家庭数据按绑定关系隔离。
10. 平台管理员可创建、绑定、解绑、重置、解锁、停用或删除家庭账号；删除家庭时同时逻辑删除该守护人绑定的安心用药账号，历史业务记录保留审计。
11. 登录前未完成人机验证时，点击登录会明确提示，不再表现为按钮无反应。
12. 图片上传支持 JPG、JPEG、PNG、GIF、WEBP，限制 5MB，并校验文件签名，防止只改扩展名伪装图片。

## 5. 图片与 OCR 结论

图片上传已经实现并通过文件签名单元测试；上传后的订单截图和收货照片可作为人工核验凭证。

OCR 光学识别本版本没有实现。当前不会自动从照片识别药名、国药准字号或数量，也不会假装给出识别结果。接口和页面流程已为后续接入 OCR 保留业务位置，后续可以增加“识别结果 + 人工确认”，但不能用 OCR 结果直接替代收货人核对。

## 7. 阿里云人工验收清单

部署成功后按顺序完成：

1. 用 `admin/admin` 登录，创建一个 GUARDIAN 和一个 ELDER，完成绑定、解绑、重新绑定。
2. 分别登录两个安心用药账号，打开“今日用药”，确认晨间、午间、晚间均有药品卡片且不再报无权限。
3. 不点击“确认你是真人”，直接点登录，确认页面出现明确提示。
4. 在手机上打开用药方案、购药记录、家庭与用户，确认右侧只有窄“操作”按钮，不遮挡主要字段。
5. 打开“登记家庭购药转账”和“新增方案”，连续点击输入项并拉起键盘，确认标题与右上角关闭按钮始终可见。
6. 安心用药端提交购药申请；平台端先只阅读消息，确认状态从“未读待处理”变为“已读待处理”。
7. 平台端上传下单截图、填写预计到货时间并登记订单，确认状态变为“已购买”。
8. 更新物流为运输中、送达，确认依次显示“配送中”“待收货核验”。
9. 安心用药端上传收货合照，分别测试数量/准字号/包装/规格剂量全部一致和任一不一致。
10. 核验全部一致时确认库存入账、业务状态“已完成”；不一致时确认不入库并通知家属。
11. 用 GUARDIAN A 尝试访问 GUARDIAN B 的成员、方案、购药记录、订单与统计，预期全部拒绝或返回空范围。

## 8. 已知风险与后续建议

1. 用户指定 `admin/admin` 是弱口令，浏览器可能提示密码已泄露。这不是数据库明文泄露，而是密码过于常见。首次验收后应立即在“账号与安全”中改成独立强密码。
2. 浏览器 Network 面板在发送前会显示请求体，这是开发者工具看到的客户端原始数据；真正防止链路窃听依赖 HTTPS。公网生产环境必须配置 HTTPS，不能长期只用 HTTP。
3. BCrypt 是带随机盐的单向密码哈希，公开算法名称不会使密码可逆；直接使用 SHA-256 保存密码反而更容易遭受高速字典攻击。页面已改成通俗的“密码单向安全存储”，不再展示算法名。
4. 前端构建仍提示 Element Plus 和图表包较大，不影响本次构建与功能，但后续可做按需图标和报表模块延迟加载，继续优化首屏性能。
5. 当前使用数据库事务和站内消息即可满足项目体量，不引入 MQ，避免增加部署和运维复杂度。业务量显著增长后再评估消息队列。
